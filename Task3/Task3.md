## 1. Требования к безопасности

| № | Требование | Описание |
|---|---|---|
| 1 | Защищённое соединение | Все запросы между PropDevelopment и партнёром выполняются по HTTPS (TLS 1.2+). |
| 2 | Аутентификация | Пользователи проходят аутентификацию в мобильном приложении. Внешние системы аутентифицируют друг друга при обращении к API. |
| 3 | Авторизация | Внешние сервисы поддерживают протокол OAuth 2.0 Client Credentials для авторизации tenant-core-app. |
| 4 | Изоляция данных | Партнёр получает данные только тех жилых комплексов и устройств, которые он обслуживает. |
| 5 | Минимизация данных | Партнёру передаются только необходимые идентификаторы устройств, разрешения и автомобильные номера. Биометрические данные обрабатываются на стороне партнёра. |
| 6 | Защита персональных данных | Обработка персональных и биометрических данных должна соответствовать требованиям 152-ФЗ. Для биометрии необходимо обеспечить соответствующее правовое основание, включая согласие в предусмотренных законом случаях. |
| 7 | Журналирование | Система фиксирует действия пользователей, изменения списков доступа и события открытия устройств. |
| 8 | Защита вебхуков | Входящие вебхуки должны проходить аутентификацию и проверку подлинности. Повторная обработка одного события должна исключаться. |

## 2. Протоколы аутентификации и авторизации

- Запросы от приложения tenant-core-app ко внешним сервисам "Умный шлагбаум" и "Умный домофон" - по протоколу REST API с авторизацией через OAuth 2.0 Client Credentials
- Запросы от внешних сервисов к tenant-core-app - по HTTPS через вебхуки с проверкой подписи HMAC

## 3. Организация взаимодействия между системами

### 3.1. Передача разрешений на доступ

1. Собственник настраивает доступ к домофону или шлагбауму в мобильном приложении.
2. Мобильное приложение отправляет запрос в tenant-core-app.
3. tenant-core-app проверяет права собственника и сохраняет изменения в tenant-core-db.
4. tenant-core-app отправляет обновлённый список разрешений партнёру через REST API, например PUT /access-lists.
5. Партнёр подтверждает успешное применение списка либо возвращает ошибку.


### 3.2. Открытие устройства по запросу

1. Собственник нажимает кнопку открытия домофона или шлагбаума.
2. Мобильное приложение отправляет запрос в tenant-core-app.
3. tenant-core-app проверяет право пользователя управлять устройством.
4. При успешной проверке сервис отправляет команду партнёру через HTTPS REST API.
5. Партнёр выполняет команду и возвращает её результат.

### 3.3. Автоматическое открытие

1. Камера партнёра распознаёт лицо человека или номер автомобиля.
2. Платформа партнёра сравнивает результат с разрешённым списком.
3. Если доступ разрешён, партнёр открывает дверь или шлагбаум.
4. Партнёр отправляет событие в tenant-core-app через вебхук POST /events.
5. tenant-core-app проверяет подлинность события и сохраняет его в tenant-core-db.
